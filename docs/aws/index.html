Early-access deployment · AWS

Deploy Fort on
AWS.

Download the templates, configure your cloud and sign in to Fort.

One VM in your cloud, with an encrypted retained disk and a stable IP. HTTPS console access is restricted to your network on port 7451; internal services stay private. This is a single-VM installation, without high availability.

Download Terraform templates ↓

AWS + Google Cloud · includes shared bootstrap and operating reference · SHA-256 checksum. Qualified Fort binaries are supplied separately by your Fort contact. These templates have offline validation; qualify the VM, network, TLS and sign-in in your environment.

1. Have these ready.

  • Terraform ≥ 1.9 and < 2.0, cloud deployment credentials and an encrypted, access-controlled state backend. Review cloud costs.
  • An existing VPC/public subnet and a pinned Canonical Ubuntu 24.04 amd64 AMI (owner 099720109477). Choose an EC2 maintenance key at launch if you will need SSH.
  • A DNS hostname, trusted matching TLS certificate/key and a protected bootstrap secret with an immutable version.
  • Company SSO: an OIDC issuer with discovery, device authorization and browser authorization-code + PKCE; client IDs and a first administrator group or immutable subject.
  • Direct HTTPS URLs and trusted SHA-256 hashes for fort and fortd from the same qualified Linux x86_64 build, including console assets.

Register https://YOUR_HOSTNAME:7451/auth/callback for the browser client. SSO setup is required before applying. Client and administrator setup ↗ · Secret format and cloud prerequisites ↗

2. Configure the template.

Extract the ZIP and keep aws, gcp and shared together. In fort-terraform-customer/aws, copy the example:

Replace every placeholder: cloud location/image, bootstrap-secret reference/version, allowed console_cidrs, hostname, binary URLs/hashes, OIDC clients and administrator. The example documents each field; see the full configuration reference.

Keep private keys and client-secret values in the cloud bootstrap secret, never in tfvars, policy, command arguments or VM metadata. Use your actual IPv4 egress ranges; whole-internet access is refused. SSH is closed by default; arrange an approved maintenance path before launch.

3. Review, apply and open Fort.

If you did not set a DNS-zone input, point your hostname’s A record at terraform output -raw public_ip; do not add an AAAA record.

Terraform completion is not installation readiness. Wait for Fort bootstrap ready: https://... in EC2 console output. Then open the returned HTTPS URL from an allowed network, check TLS without an exception and sign in with the configured SSO administrator.

Confirm Agents and Access are available, unassigned users have no admin access, and internal ports remain private. Approval decisions require a separate human step-up. Readiness checks ↗

4. Connect your first agent.

Prepare separate agent and tool-server images. Backend credentials belong in the tool server, outside the agent sandbox. Configure the agent’s MCP client, then verify one allowed read-only call and its ledger decision.
